# Gaps — composer-draft-shopping

Decisions locked in [`STORY.md`](STORY.md). Track half-open items here; resolve before or during the owning WI.

| ID    | Topic                           | Status                  | Notes                                                                                                                                                                                                                                                                                                                                                                                                              |
| ----- | ------------------------------- | ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| G-S1  | `anno-expr` compatibility       | **resolved**            | Leave `anno-expr` semantics, bindings, and pushdown **unchanged**. New key is `obj-expr` only.                                                                                                                                                                                                                                                                                                                     |
| G-S2  | `obj-expr` binding namespaces   | **resolved**            | `a` = annotations map; `p` = payload map; top-level `id`, `type`, `schemaVersion` (string or null). Dot and bracket access on maps.                                                                                                                                                                                                                                                                                |
| G-S3  | Nested payload paths            | **resolved (v1)**       | Allow nested map access where payload already has nested objects (`p.address.city`). Arrays: index access only if JEXL allows without method calls; **no** collection predicates in v1. Document examples for top-level scalars first.                                                                                                                                                                             |
| G-S4  | `obj-expr` SQL pushdown         | **resolved (strategy)** | **Same pattern as `anno-expr`**: lower what we can to a candidate source; otherwise **local eval**. WI-001 implements lowerers for equality/`&&`/`\|\|` over `type`, `id`, `schemaVersion`, `a.*` (annotations `@>`), and `p.*` (payload `@>` when backend supports it). Non-lowerable ops → local JEXL. No GIN on payload yet is OK — `@>` still works; index work stays a persistence follow-up.                 |
| G-S5  | Candidate exposure + lazy JSON  | **resolved**            | Expose **`id` / `type` / `schemaVersion` / `a` / `p`** on candidates for `obj-expr`. **Same strategy as annotations:** column projection includes JSON only when the plan needs it; values stay in `LazyJsonMap` and **deserialize only on access**. Do **not** force eager full-map build. Push down when possible (G-S4); survivors hydrate any deferred columns before response mapping (existing reader path). |
| G-S6  | Edge refresh API shape          | **resolved**            | New DSL key **`ids`**: `{ "ids": ["uuid", …] }` selects those entities + **induced** edges (same induction rule as today). Used for Composer Done merge; valid anywhere `/graph/query` accepts matchers. Empty `ids` → empty subgraph. Invalid UUID → **400** (WI-003).                                                                                                                                            |
| G-S7  | Id already in draft             | **resolved**            | **Keep draft** entity/edge; skip overwrite from search/edge merge.                                                                                                                                                                                                                                                                                                                                                 |
| G-S8  | Exclude vs Delete               | **resolved**            | **Remove from draft** = exclude (no `pendingDelete*`). **Delete** = existing Apply delete path. Exclude of entity drops incident draft edges via exclude (not pending delete) unless those edges were already pending-delete.                                                                                                                                                                                      |
| G-S9  | When draft updates in Add objects modal | **resolved**            | **Immediate**: Add / In-draft toggle mutates draft while modal is open. **Done** only runs induced-edge merge among current store-backed draft ids, then closes.                                                                                                                                                                                                                                                   |
| G-S10 | Store-backed vs user-created    | **resolved**            | Store-backed = entity id in `baselineEntityIds` (merged from store) and not `new`-only. User-created (`draftStatus` new / not in baseline) **excluded** from id-set edge refresh.                                                                                                                                                                                                                                  |
| G-S11 | Results table columns           | **resolved (v1)**       | Fixed: **id**, **type**, then up to **6** top-level **scalar** payload fields (string/number/boolean; skip objects/arrays). Truncate cell text. No schema-driven column picker in v1.                                                                                                                                                                                                                              |
| G-S12 | Composer button label           | **resolved**            | **Add objects…** (not “Load…”). Never “Shop…” / shopping / cart in UI. |
| G-S13 | Matcher form defaults           | **resolved**            | Composer modal default mode **`obj-expr`**. Explorer / Query keep existing default (`anno`) but offer `obj-expr` in the mode list.                                                                                                                                                                                                                                                                                 |
| G-S14 | Explorer → Composer handoff     | **resolved**            | Open Composer; run Search with nav matcher; **auto-merge all hits + induced edges** into draft (append); close Add objects. Do **not** replace draft. |
| G-S15 | `qid` / selection URL           | **resolved**            | Modal **Search** success calls `beginQueryResult()` → **new `qid`** (same as old Load), so result selection can deep-link via `node`/`edge` params.                                                                                                                                                                                                                                                                |
| G-S16 | Soft-deleted chrome vs exclude  | **resolved**            | Exclude does **not** use soft-deleted / “deleted” icons. Pending-delete soft-delete UI remains only for Delete.                                                                                                                                                                                                                                                                                                    |
| G-S17 | Result size / caps              | **resolved**            | Add objects results table: **client-side pagination**, page size **20**. Full match set stays in memory from Search; UI shows 20 rows + page controls. No server-side limit/offset in this story. |
| G-S18 | Field-builder UI for `obj-expr` | **deferred**            | **No** type/payload field builder in this story. Users author **`obj-expr` as JEXL text** (same as typing `anno-expr`). A form that emits `obj-expr` is a follow-up. |
| G-S19 | Shared JEXL engine              | **resolved**            | **Share** `BoMAnnoExprEngine` (same sandbox permissions/features/cache). Separate compile helpers / error codes `MATCHER_OBJ_EXPR_*` for `obj-expr` only; do not change `anno-expr` error codes. |
| G-S20 | Chaining                        | **resolved**            | `obj-expr` and `ids` participate in ordered arrays like other keys. Only stage 0 may be source-capable; **`obj-expr` is source-capable when lowerable** (G-S4), else filter/local-eval. `ids` **is** source-capable (id IN list). Visual chain builder stages: `anno` / `anno-expr` / `obj-expr` (not `ids` in v1 — G-S22). |
| G-S21 | `obj-expr` on all matcher UIs   | **resolved**            | Add **`obj-expr`** to shared [`MatcherQueryForm`](../../../../objs-service/ui/src/MatcherQueryForm.tsx). Surfaces: Explorer, Query, Composer Add objects modal — wherever the form is used. |
| G-S22 | Visual chained matcher builder  | **resolved**            | Chained mode: **Visual** list of stages — each stage has a kind select (`anno` \| `anno-expr` \| `obj-expr`) and the **same visual editor as the standalone mode** for that kind (anno key/value rows; anno-expr / obj-expr JEXL textarea). Add / delete / move up-down. **JSON** is a separate toggle for the **entire chain document only** (pretty-printed array) — not per-stage JSON. Round-trip Visual ↔ full-chain JSON when JSON valid. Up/down buttons (no DnD lib in v1). WI-006. |
| G-S23 | No shop/cart product language   | **resolved**            | Story slug/branch may keep `composer-draft-shopping`. **Never** use shop / shopping / cart in UI strings, React component names, CSS classes, test ids, or other product identifiers. Prefer Add objects, merge, exclude, draft. |
