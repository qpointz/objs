# Objs API and application-local graph codegen

This document describes the boundary between the schema-agnostic runtime and generated
application code.

## Ownership

Root `objs-*` modules provide generic graph primitives and runtime behavior. They do not contain
application ontology classes or generated entity bindings. A consuming application owns:

1. JSON Schema payload DTOs generated by `jsonschema2pojo`;
2. typed entity and read-node bindings generated by `objs-codegen-java`; and
3. its schema-specific graph builder and read facade.

The public `BoM`-prefixed library rename is an intentional source and binary break. JSON mutation
fields, REST paths, and JPA entity names retain their established wire/storage names; persistence
tables use the `objs_*` namespace after the forward migration.

The normal consumer lifecycle is:

```text
jsonschema2pojo → objs-codegen-java → Java compilation → application tests
```

`objs-api` is Kotlin/JVM, Java-compatible, Spring-free, JPA-free, and persistence-free. Payload
conversion uses a `PayloadMapper` constructed with the consuming application's configured Jackson
`ObjectMapper`; no default mapper is created by the API.

## Generated types

For an entity such as `Product`, generated code has three distinct handles:

| Type | Role |
|---|---|
| `ProductNode` | Write-side typed entity handle. Used by the mutation builder. |
| `ProductReadNode` | Read-only facade over a snapshot node. Provides typed navigation. |
| `ProductRef` | Identity-only reference containing the UUID. |

`ProductNode` and `ProductReadNode` are not interchangeable. A read node cannot persist or mutate
the graph. A write node does not imply persistence; it is only converted into an `Entity` when the
generated mutation builder is built.

## Write model

Generated payload DTOs contain payload attributes. Relations are not serialized as nested entity
collections in a mutation. The generated `GraphMutationBuilder` creates entities and explicit
edges:

```java
PayloadMapper mapper = new PayloadMapper(configuredObjectMapper);
GraphMutationBuilder builder = new GraphMutationBuilder(mapper);

ProductNode product = builder.addProduct(new Product().withName("Payments"));
ComponentNode component = builder.addComponent(new Component().withName("Jackson"));
builder.containsComponent(product, component);

GraphMutation mutation = builder.build();
```

`add<Type>(pojo)` assigns a provisional UUID. An overload accepts an explicit UUID. Duplicate
entity and edge UUID registration fails; equal payloads with different UUIDs remain distinct.
`MutationMode.MERGE` is the default and `MutationMode.REPLACE` is selectable through the builder
constructor or `mode`.

Deletion is represented by UUIDs in the mutation's `unset` collections. It uses the same builder
but does not require reconstructing the payload or edge:

```java
GraphMutationBuilder deletion = new GraphMutationBuilder(mapper);
deletion.unsetEdge(existingEdgeId);
deletion.unsetEntity(existingEntityId);
GraphMutation deleteMutation = deletion.build();
```

The resulting `GraphMutation` has empty `set` collections, while
`deleteMutation.getEdges().getUnset()` and `deleteMutation.getEntities().getUnset()` contain the
requested UUIDs. The default `MERGE` mode makes this a deletion patch; strict existence and
authorization checks remain the responsibility of the object store.

Only exact, generated allow-list relations are exposed as typed relation methods. Wildcard rules
remain runtime metadata unless a safe static binding can be generated. Mutation building does not
perform persistence or strict server validation.

## Edge properties

`NONE` is authoritative: its generated relation method has no property argument and creates an
edge with `properties == null`.

`SCHEMA` generates a property argument for the resolved edge-property DTO. If the schema reference
cannot be resolved, the generator retains the relation and uses a generic map representation
with a diagnostic. `emptyPropertiesAllowed` controls whether the property-free overload is
available. These are construction-time conveniences; strict schema and relation acceptance remains
at the object-store boundary.

## Read model

`GeneratedReadView.from(graph, mapper)` wraps an in-memory `TypedGraphView` and supplies exact
`(type, schemaVersion)` payload bindings. It never loads from or writes to an object store.

```java
GeneratedReadView view = GeneratedReadView.from(graph, mapper);
ProductReadNode product = view.products().get(0);
TypedCollection<ComponentReadNode> components =
    product.getContainsComponents();
TypedCollection<RelationEdgeView> edges =
    product.getContainsComponentEdges();
```

Generated collection navigation follows the original directed edge. Generic `edges(role,
direction)` and relation-edge collections preserve edge properties and expose unresolved endpoint
IDs. Inbound navigation does not create a synthetic reverse edge.

Collections are immutable snapshots. A `1:1` relation additionally exposes a singular accessor:
zero matches return `null`, and multiple resolved matches throw `AmbiguousRelationException`.
Cardinality metadata is not a persist-time count constraint.

Unknown types, dangling endpoints, obsolete relations, schema drift, and missing historical
bindings remain available through the raw `TypedGraphView` and `RelationEdgeView` APIs. Exact
hydration is optional; raw snapshot reads do not require a schema registry. An application may
adapt an existing registry through `TypedEntityBindingRegistry` when it needs lazy exact-version
hydration.

## Schema metadata

The `json-schema-codegen` export adds `x-objs-relations` and `x-objs-codegen` only to the codegen
format. Standard catalog export remains unchanged. 2020-12 documents use `$defs`; draft-07
documents use `definitions`, with dialect-correct references.

Schema and relation attributes can override generated Java symbols. The `codegen.*` keys are
consumed by the Objs exporter/generator; they are not JSON Schema keywords.

| Key                           | Applies to              | Effect                                                                                                                                                                                                               | Default                                |
| ----------------------------- | ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------- |
| `codegen.java.typeName`       | Schema attributes       | Overrides the Java payload type name used by generated nodes, refs, builders, and read bindings.                                                                                                                     | Normalized schema definition key       |
| `codegen.baseClass`           | Schema attributes       | Makes the generated node extend the supplied Java type instead of the default `GeneratedNode<Payload>`. The type must be a valid Java type reference and provide the constructor/API expected by the generated node. | `GeneratedNode<Payload>`               |
| `codegen.interfaces`          | Schema attributes       | Adds comma-separated Java interfaces to the generated node. The standard read/write capability interfaces are still added.                                                                                           | No custom interfaces                   |
| `codegen.baseClass`           | Relation attributes     | Supplies the custom base binding needed to statically generate a wildcard endpoint relation.                                                                                                                         | Wildcard relation remains runtime-only |
| `codegen.java.outboundMethod` | Relation attributes     | Overrides the method on the source node/builder for the outbound relation.                                                                                                                                           | Normalized role-plus-target name       |
| `codegen.java.inboundMethod`  | Relation attributes     | Overrides the inverse navigation method on the target read node.                                                                                                                                                     | Normalized role-plus-source name       |
| `codegen.java.skip`           | Schema or relation tags | Suppresses the corresponding typed binding. For a schema, the entity binding is skipped; for a relation, its generated relation methods are skipped.                                                                 | `false`                                |
| `codegen.java.noInverse`      | Relation tags           | Keeps outbound relation generation but suppresses the inbound/inverse read navigation.                                                                                                                               | `false`                                |

`codegen.java.typeName` controls the name expected by the behavioral generator; it does not
reconfigure `jsonschema2pojo`. If an override is used, the DTO generator must emit a matching
class name (or the consuming build must provide that class).

Missing overrides use the existing normalization. Blank or invalid symbols and post-override
collisions fail deterministically. The exported relation `codegen` object also records the
effective `skip`, `noInverse`, method names, static-binding decisions, and wildcard flags; those
are generator metadata, not additional authoring keys.

## Verification

The repository consumer examples exercise both dialects:

```text
./gradlew -p examples/codegen/jsonschema test
./gradlew -p examples/codegen/jsonschema-draft07 test
```

The examples consume the root generator through a Gradle composite build. Generated output stays
under each example's `build/generated` directory and is never written into a root `objs-*`
module.
